# Материализация

**Способ, которым dbt превращает SELECT модели в объект базы: view (запрос), table (данные, атомарная подмена через переименование), incremental (только новое), ephemeral (CTE внутри потребителей).** Выбор — компромисс между ценой сборки, ценой чтения и свежестью.

> [!tip] Аналогия
> Посуда: готовить по заказу, держать готовым на раздаче, доготавливать свежую порцию или использовать внутри другого блюда.

**У нас:** DuckDB 1.5 не умеет для Iceberg `CREATE OR REPLACE`, представления и переименование изменённой в транзакции таблицы → `table` в Iceberg падает; модели — в DuckDB-файле, публикация — DROP + CTAS с `transaction: false`.

# Публикация порта (`ports`) и DNAT

**Правило Docker «подключения на такой-то порт хоста переправляй в контейнер»**. Работает
двумя механизмами сразу:

- **`docker-proxy`** — процесс на хосте, который слушает порт хоста и сам соединяется с
  контейнером. Поэтому `ss -ltn` показывает порт как занятый.
- **DNAT** (Destination NAT) — правило iptables, которое у пакетов из сети подменяет адрес
  назначения: `<хост>:9000` → `172.28.0.3:9000`.

```text
"127.0.0.1 : 9000 : 9000"
 IP хоста    порт   порт
 (где        хоста  контейнера
 слушать)
```

> [!tip] Аналогия
> Переадресация на ресепшене здания: позвонил ресепшену на добавочный 9000 — соединили с Silo.

- Нужна **только для входа с хоста** (браузер, DBeaver, curl на хосте). Контейнерам одной
  сети она не нужна.
- `127.0.0.1:` — принимать только с этой машины. Без IP — со всех интерфейсов (Wi-Fi, LAN, VPN).
- Правила Docker срабатывают **раньше** [файрвола](firewall.md) `ufw`.

**Посмотреть:** `docker port debd-silo-1`, `ss -ltn`.

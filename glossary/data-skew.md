# Перекос данных (skew)

**Неравномерное распределение строк по ключу: все строки ключа попадают в одну партицию shuffle, одна задача работает дольше остальных, стадия ждёт её. Видно по метрикам стадии: максимум времени задачи ≫ медианы, spill у одной задачи.** Лечат broadcast, агрегацией до соединения, солью (случайный суффикс ключа + размножение маленькой стороны), AQE skew join.

> [!tip] Аналогия
> Половина фамилий — «Иванов», и все достаются одному рабочему.

**У нас:** город 0 — 52 % строк (2 322 990 из 4,5 млн). Sort-merge по `city_id`: задачи 4,2 / 9,1 с; с солью 8 — 4,1 / 4,3 с.

# Кэш сборки

**Хранилище готовых слоёв, которое позволяет не выполнять шаг сборки повторно.** Перед каждой
инструкцией BuildKit вычисляет ключ: ключ предыдущего шага + текст инструкции с подставленными
`ARG` + для `COPY` контрольные суммы файлов. Есть слой с таким ключом — шаг помечается `CACHED`.

> [!tip] Аналогия
> Архив готовых листов проекта: если пункт техзадания и всё выше него не менялись, лист берут
> из архива.

**Каскад:** если шаг выполнился заново, у всех шагов ниже новые ключи, и они тоже выполняются.

**Неочевидное:**
- для `RUN` важен только текст команды: отдельный `RUN apt-get update` навсегда застрянет в кэше;
- для `COPY` важно содержимое, а не дата: `touch` кэш не ломает;
- все `ARG`, объявленные выше, входят в ключ каждого `RUN`, даже если он их не использует.

**Посмотреть:** `docker compose build --progress plain <сервис>` — строки `CACHED`.
**Выключить:** `--no-cache`.

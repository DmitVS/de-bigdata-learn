Решение пользователя от 2026-10-01. До него lineage встречался только в модуле 11, а
документация — одним пунктом «`dbt docs`» в модуле 05.

**Интерактивная документация** — сайт, который собирается из кода и метаданных и по которому
можно кликать. Отдельно в курс включены **отчёты-страницы**, где текст, SQL и графики живут вместе.

| Модуль | Что добавлено |
|---|---|
| 05 | урок о документации и lineage в dbt: YAML-описания, docs blocks, `persist_docs`, анализ влияния через `dbt ls --select +модель+`; лаба 05.4; проверка, что у marts есть описания |
| 06 | граф ассетов Dagster от загрузки до витрин как DoD; задача «что пересчитать после сбоя» |
| 09 | источник плохих данных в разборе инцидента ищется по lineage |
| 10 | отчёт-страница на Evidence (альтернатива — Quarto); лаба 10.4 |
| 11 | урок о теории lineage и стандарте OpenLineage; в лабе 11.2 lineage из Spark через OpenLineage в OpenMetadata |
| 12 | `dbt docs generate` в CI и публикация на GitHub Pages |

**Почему OpenLineage:** открытый стандарт событий lineage, поддерживаемый Spark, dbt, Dagster и
Airflow. Без него в граф не попадают трансформации Spark (модуль 07): dbt о них не знает.

**Почему Evidence:** markdown + SQL, есть коннектор DuckDB, собирается в статический сайт,
открытый исходный код. Quarto — запасной вариант, если нужен Python в отчёте. Evidence требует
Node.js, поэтому по правилу [containers-only](containers-only.md) он запускается отдельным
сервисом в слое `serving.yaml`. Порт хоста — **3001**, потому что 3000 зарезервирован под Dagster.

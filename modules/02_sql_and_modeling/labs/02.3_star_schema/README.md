## Objective

Спроектировать по Кимбаллу звёздную схему для продаж и наличия сети, обосновать место каждой
колонки проверкой запросом, нарисовать ER-диаграмму и загрузить звезду в DuckDB. Эта модель —
прототип gold-слоя, который в модуле 05 будет построен в dbt.

## Tasks

### Task 1. Четыре шага и место каждой колонки

**Expected result / Definition of Done:**
- В README: процесс(ы), grain каждой таблицы фактов одним предложением, список измерений и мер
- Таблица «колонка источника → от чего зависит (запрос проверки) → куда кладём»: все 19 колонок
- Обоснованное решение по погоде, `discount` и `activity_flag` с альтернативой, которую отверг

**Steps:**
1. Пройди 4 шага Кимбалла (урок 05, шаг 1). Подумай, нужен ли второй факт с grain по часам.
2. Для каждой колонки проверь функциональную зависимость (урок 05, шаг 2). Начни с кандидатов:
   товар, магазин, дата, магазин × дата, товар × дата.
3. Для погоды разбери два варианта из урока и выбери один.

### Task 2. ER-диаграмма

**Expected result / Definition of Done:**
- Mermaid `erDiagram` в README: все факты и измерения, ключи `PK`/`FK`, связи с кардинальностью
- Диаграмма отображается в Obsidian без ошибок

**Steps:**
1. По синтаксису урока 05, шаг 5: каждая связь `||--o{`, каждый атрибут на своей строке.
2. Если два факта используют одни измерения, отметь согласованные измерения.

### Task 3. DDL и загрузка

**Expected result / Definition of Done:**
- Файл `star.sql`: `CREATE TABLE` всех таблиц и запросы загрузки из Parquet
- База `data/warehouse/star.duckdb` создаётся командой
  `duckdb data/warehouse/star.duckdb < modules/02_sql_and_modeling/labs/02.3_star_schema/star.sql`
- Суррогатные ключи у измерений; `dim_date` сгенерирован; строка «неизвестно» (`-1`) хотя бы в
  одном измерении
- Проверки в `queries.sql`: строк в факте = строк источника на его grain; ключ факта уникален; у
  каждого FK есть пара в измерении; суммы мер совпадают с источником

**Steps:**
1. Суррогатные ключи можно выдать через `row_number() OVER (ORDER BY естественный_ключ)`.
2. Календарь — по примеру урока 05, шаг 4, с теми атрибутами, которые нужны твоим вопросам.
3. При загрузке факта соединяй источник с измерениями по естественному ключу и записывай
   суррогатный. Сравни число строк до и после — размножения быть не должно.
4. `mkdir -p data/warehouse` в `make shell`. Файлы `*.duckdb` уже в `.gitignore`.

### Task 4. Запросы к звезде

**Expected result / Definition of Done:**
- Три запроса к звезде: по одному на разные измерения (город, категория, день недели или
  праздник), каждый — факт плюс соединения с измерениями
- Результат каждого совпадает с тем же запросом к исходной плоской таблице

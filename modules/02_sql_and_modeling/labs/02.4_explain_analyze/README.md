**Модуль:** [02 · SQL и моделирование](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Научиться объяснять скорость запроса планом, а не догадками. Одна задача — доля часов без товара
по магазинам — решается тремя способами по разным данным; надо доказать, что результаты
одинаковы, замерить и объяснить разницу операторами плана.

## Tasks

### Task 1. Три варианта — один ответ

**Expected result / Definition of Done:**
- Три запроса «доля часов без товара в окне 6:00–22:00 по каждому магазину»:
  (A) по `stock_hour6_22_cnt` исходных файлов; (B) по `hours_stock_status` исходных файлов без
  полного разворота (функции списков); (C) по `sales_hourly.parquet`
- Запрос-сверка: результаты трёх вариантов совпадают для всех 898 магазинов (с допуском)

**Steps:**
1. Убедись, что все три варианта считают одно и то же окно часов. Расхождение — почти всегда
   ошибка на единицу в границах окна.
2. Для (B) вспомни срезы списков и `list_sum` (модуль 00, урок 09; урок 03 этого модуля).

### Task 2. Планы

**Expected result / Definition of Done:**
- Для каждого варианта `EXPLAIN ANALYZE` в README (можно сокращённо): операторы снизу вверх,
  `Projections`, `Filters`, строки на выходе каждого оператора
- Ответ: какой оператор в каждом варианте самый дорогой и почему

### Task 3. Замер и объяснение

**Expected result / Definition of Done:**
- По 30 запусков каждого варианта: p50, p95 и первый запуск отдельно (скрипт из модуля 01)
- Объяснение порядка вариантов по скорости через планы: сколько колонок и строк читает каждый
- Вывод: какой источник выбрать для витрины «доля пустых часов» и почему

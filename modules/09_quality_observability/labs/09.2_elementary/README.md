## Objective

Подключить Elementary к dbt-проекту capstone: история запусков и тестов в одном отчёте, мониторы
объёма и распределений на ключевых таблицах. Понять, где детекторы аномалий полезны, а где на
наших данных бессильны и чем их заменить.

## Tasks

### Task 1. Elementary в capstone

**Expected result / Definition of Done:**
- Пакет подключён, служебные таблицы в отдельной схеме; `dbt build` зелёный
- `edr report` собирает отчёт в `data/`; в README — что в нём видно: последние запуски, покрытие
  тестами, lineage

### Task 2. Мониторы

**Expected result / Definition of Done:**
- `volume_anomalies` на факте продаж, `dimension_anomalies` по городу, `column_anomalies` на
  одной метрике витрины; параметры окон и корзин обоснованы
- В README — ответ: почему на датах датасета (2024) эти мониторы ничего не находят, и проверка
  этого ответа запросом к `main_elementary.data_monitoring_metrics` (или аналогу в твоей схеме)

### Task 3. Аномалия, которую поймали

**Expected result / Definition of Done:**
- На учебной базе модуля (`demo/build_demo_db.py`) воспроизведены два инцидента, которые ловит
  **только** детектор, а не тест с правилом (придумай их сам; генератор можно не трогать, а менять
  данные запросом)
- Для каждого — описание из `elementary_test_results` и график в отчёте
- Сезонность: проверено, срабатывает ли `volume_anomalies` на днях недели, и нужна ли
  `seasonality` на наших данных (запрос, вывод)

## Objective

Собрать качество capstone в одну систему: контракты на границах, тесты на моделях, мониторы на
ключевых таблицах, сверка с источником, SLO и инструкция дежурного. Результат — ответ на
бизнес-вопрос модуля: сеть узнаёт о проблеме в данных раньше, чем её заметит аналитик.

## Tasks

### Task 1. Карта проверок

**Expected result / Definition of Done:**
- Таблица в `capstone/quality/README.md`: таблица → слой → измерения качества → проверка
  (инструмент) → уровень → кто реагирует. Без дублирования одной проверки на нескольких слоях
- Контракт dbt на витринах, которые читают внешние движки (`contract: enforced`)

### Task 2. Всё в pipeline

**Expected result / Definition of Done:**
- Ночной запуск Dagster: свежесть источников → Soda на bronze (ворота) → dbt build с тестами и
  Elementary → сверка витрин с bronze → отчёт `edr report`
- Сценарий «грязная ночь» из трёх одновременных сбоев (на твой выбор): все пойманы, витрины не
  испорчены, в UI и отчёте понятно, что случилось

### Task 3. Capstone

**Expected result / Definition of Done:**
- В [`capstone/README.md`](../../../../capstone/README.md) — раздел «Quality»: карта проверок, SLO,
  как смотреть отчёт, runbook «симптом → где смотреть → что делать» (дополняет runbook модуля 06)
- Пункты DoD модуля 09 в [`ROADMAP.md`](../../../../ROADMAP.md) отмечены по факту

## Tasks

### Task 1. Схемы: контекст и компоненты

**Expected result / Definition of Done:**
- Файл [`capstone/architecture.md`](../../../../capstone/architecture.md) по структуре урока 06, шаг 4
- Две Mermaid-схемы, которые отображаются в Obsidian без ошибок: контекст и компоненты
- На схеме компонентов: все этапы MDS, инструмент и модуль курса у каждого, слои
  bronze/silver/gold, оркестрация пунктиром, подписи на стрелках «что и как часто»

**Steps:**
1. Выпиши из карточек 01.2 все источники, потребителей и требуемую частоту обновления.
2. Нарисуй контекстную схему: платформа одним узлом (урок 06, шаг 1).
3. Нарисуй схему компонентов по таблице этапов из урока 03, шаг 1. Используй группы для
   этапов и цилиндры для хранилищ (урок 06, шаг 2).
4. Открой файл в Obsidian и убедись, что обе схемы отрисовались.

### Task 2. Слои и решения

**Expected result / Definition of Done:**
- Раздел «Слои данных»: таблица слой → таблицы → grain → кто читает; gold-таблицы связаны с
  карточками вопросов из 01.2
- Минимум 3 ADR: (1) ETL vs ELT, (2) lakehouse vs warehouse vs lake, (3) батч vs стриминг для
  capstone; у каждого 2–3 варианта, решение и последствия
- Раздел «Известные ограничения»: минимум 3 пункта

**Steps:**
1. Для каждой карточки 01.2 определи gold-витрину и проверь, что её можно собрать из silver
   (урок 04, шаг 4).
2. Напиши ADR по формату урока 06, шаг 3. Контекст бери из своих NFR (Task 3), а не общими
   словами. ADR про lakehouse можно начать с примера из урока, но варианты и последствия
   перепиши под свои вопросы.
3. Ограничения бери из урока 02, шаг 3, и из своих NFR.

### Task 3. Нефункциональные требования с числами

**Expected result / Definition of Done:**
- Раздел NFR: таблица параметров нагрузки с числами, посчитанными запросом (объём в сутки,
  детальность, история)
- SLO для минимум трёх показателей: свежесть, полнота, задержка — с процентом и периодом
- Замер p50/p95/p99 одного запроса к будущей gold-витрине (не меньше 100 запусков), отдельно
  указан первый запуск; скрипт или команда — в README

**Steps:**
1. Посчитай параметры нагрузки запросами (урок 05, шаг 2) и сохрани их в `queries.sql`.
2. Выбери самый частый запрос дашборда из своих карточек и замерь его скриптом из урока 05,
   шаг 3 (`method="inclusive"`).
3. Запиши SLO в формате SLI + цель + процент + период (урок 05, шаг 5).
4. Отметь в ROADMAP пункт DoD про `capstone/architecture.md`.

# Лаба 11.3 · Доступы: роли, маскирование и фильтры строк

**Модуль:** [11 · Governance](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Сделать так, чтобы витрины capstone были доступны разным ролям сети по-разному: менеджер города
видит свой город, партнёр — доли без товара без продаж, аналитик — всё. Правила должны работать
для любого клиента и проверяться запросом, а не честным словом.

## Tasks

### Task 1. Матрица доступа

**Expected result / Definition of Done:**
- В README — матрица «роль × таблица → права, маска, фильтр» для ролей: аналитик, менеджер
  города, партнёр, сервисный пользователь BI; для каждой ячейки — причина
- Колонки витрин capstone классифицированы (`public` / `commercial` / `PII`) метками `meta` в
  YAML dbt; в README — где эти метки видно в каталоге (лаба 11.1)

**Steps:**
1. Пройди витрины capstone и отметь чувствительные колонки.
2. Для каждой роли реши: какие таблицы, какие колонки, какие строки. Начинай с «ничего».

### Task 2. Правила в Trino

**Expected result / Definition of Done:**
- Правила для витрин capstone добавлены в `infra/docker/trino/rules.json`; учебные правила
  `partner` и `city_manager_0` можно оставить
- Для каждой роли — запросы `make trino ARGS="--user … --execute …"` и их вывод в README: что
  видно, что замаскировано, что запрещено
- Найдена и описана хотя бы одна «утечка», которую правила не закрыли (метаданные, другая
  таблица с теми же данными, вычитание итогов), и решение по ней

**Steps:**
1. Добавь правила сверху вниз: частные — выше, правило «для всех остальных» — последним.
2. Подожди 10 с (правила перечитываются) и проверь каждую роль.
3. Попробуй обойти свои правила от имени партнёра.

### Task 3. Роли в Postgres

**Expected result / Definition of Done:**
- Скрипт `capstone/governance/postgres_roles.sql`: роли-должности, права на схему, таблицы и
  колонки, политики RLS для таблиц `retail_oltp`; скрипт можно запускать повторно
- Проверка от имени каждой роли (`SET ROLE …`) — запросы и вывод в README
- Ответ в README: что увидит роль без политики после включения RLS и как ты это проверил

**Steps:**
1. Напиши скрипт так, чтобы повторный запуск не падал (`IF NOT EXISTS`, `DROP POLICY IF EXISTS`).
2. Сначала запиши предсказание для каждой роли, потом проверь.

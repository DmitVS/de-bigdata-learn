# Лаба 11.1 · OpenMetadata: каталог данных capstone

**Модуль:** [11 · Governance](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Собрать в одном каталоге все данные capstone — lakehouse, учётную систему, модели dbt, дашборды —
и дать каждой важной таблице владельца, описание, термин глоссария и метку чувствительности.
Цель — чтобы новый аналитик за пять минут нашёл витрину, понял её смысл и знал, кого спросить.

## Tasks

### Task 1. Сбор метаданных как код

**Expected result / Definition of Done:**
- Конфиги сбора в `capstone/governance/openmetadata/`: Trino (Iceberg capstone), Postgres
  (`retail_oltp`), dbt capstone, Superset; ни одного пароля или токена в файлах
- Каждый конфиг запускается `make om-ingest CFG=…` без ошибок; в README — сколько таблиц,
  моделей и дашбордов появилось в каталоге (число из вывода `metadata ingest`)
- Повторный запуск ничего не дублирует (объясни почему)

**Steps:**
1. Начни с Trino, потом dbt (ему нужны таблицы сервиса), потом Superset.
2. Ограничь сбор своими схемами (`schemaFilterPattern`).
3. Найди в UI одну таблицу из каждого сервиса и запиши её полное имя.

### Task 2. Владельцы, описания, классификация

**Expected result / Definition of Done:**
- У каждой витрины capstone — владелец (команда), описание и уровень (tier)
- Описания и владельцы витрин приходят из YAML dbt (`description`, `meta.owner`), а не правятся
  руками в UI; в README — как это проверено
- Колонки с меткой `commercial` из лабы 11.3 отмечены тегом классификации в каталоге

**Steps:**
1. Заведи команды в OpenMetadata до сбора dbt (Settings → Teams или API, образец —
   `demo/om_demo_setup.py`): иначе сбор пропустит владельцев с предупреждением.
2. Сравни описание в UI с описанием в YAML dbt после повторного сбора.

### Task 3. Глоссарий метрик

**Expected result / Definition of Done:**
- Глоссарий «Метрики сети» с терминами из лабы 10.4: продажи, часы без товара, доля часов без
  товара, доля продаж в промо — с определениями, совпадающими с семантическим слоем
- Каждый термин привязан к колонкам витрин, где он считается
- Поиск по слову «наличие» или «out-of-stock» в каталоге находит нужную витрину (проверь и
  запиши, что пришлось добавить, чтобы нашлось)

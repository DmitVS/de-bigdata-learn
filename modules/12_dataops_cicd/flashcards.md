## 01 · DataOps

Цель DataOps одной фразой?
?
Частые маленькие безопасные изменения пайплайна: всё в git, PR с ревью, автоматические проверки, тесты данных, окружения, наблюдаемость.

Четыре метрики DORA?
?
Частота выкатки, время до прода (lead time), доля неудачных изменений, время восстановления.

Почему маленькие изменения надёжнее больших?
?
Их легко отревьюить, проверить и откатить; причина поломки очевидна.

Окружения dev, CI, prod у нас?
?
dev — свой стек в Docker; CI — раннер GitHub или make ci в чистом контейнере без стека; prod — основной стек, только через конвейер после мержа.

Как DORA связана с SLO данных?
?
DORA меряет поставку кода, SLO — данные для потребителя. Исчерпан бюджет ошибок SLO — замедлить выкатки и чинить надёжность.

## 02 · pre-commit

Что делает pre-commit?
?
Перед коммитом запускает проверки файлов из индекса git по .pre-commit-config.yaml; при ошибке коммит отменяется.

Почему чинящий хук возвращает Failed?
?
Исправление не в индексе: нужно посмотреть правку и сделать git add.

Зачем у нас language: system для ruff и sqlfmt?
?
Чтобы версии линтеров совпадали с uv.lock, make lint и CI.

Как pre-commit работает без установки на хост?
?
pre-commit в образе workspace; git-хук — скрипт, который вызывает make precommit (docker compose exec).

Как не дать закоммитить .env?
?
Локальный хук language: fail с files: (^|/)\.env$ — падает, если .env попал в индекс.

## 03 · GitHub Actions

Workflow, job, step, action?
?
Workflow — YAML с событиями; job — набор шагов на отдельном чистом раннере; step — команда или action; action — готовый переиспользуемый шаг (checkout, setup-uv).

Зачем шаги CI — скрипты в репозитории?
?
Один и тот же скрипт работает в CI и локально (make ci) — CI проверяется до GitHub.

Slim CI в dbt?
?
dbt build --select state:modified+ --defer --state <manifest прода>: только изменённые модели и потомки, остальные ref — из прода.

Что делает --defer?
?
Подставляет таблицы прода для ref() на модели, которые в этом запуске не строятся.

Почему «CI зелёный» ещё не значит «проверено»?
?
Тесты могут быть пропущены: у нас 6 skipped без кластера Spark. Смотри число выполненных тестов.

Где хранить пароли для CI?
?
В Secrets репозитория (${{ secrets.ИМЯ }}); права токена — минимальные (permissions), публикация — отдельной job.

## 04 · Документация как артефакт

Что пишет dbt docs generate?
?
target/index.html (сайт), manifest.json (узлы, связи, описания), catalog.json (колонки и типы из базы).

Почему docs generate после build?
?
catalog.json читает реальные таблицы из базы — их должен создать build.

Зачем публиковать docs только из main?
?
Сайт и его manifest.json должны описывать прод; manifest с Pages — состояние прода для slim CI.

## 05 · Terraform

Цикл Terraform?
?
init (провайдеры, backend) → plan (код + state + реальность) → apply → destroy.

Что такое state и где его держать?
?
Записи о созданных ресурсах с ID и атрибутами (в т.ч. секреты). В удалённом backend с блокировкой — у нас бакет tfstate в Silo, use_lockfile.

Ресурс создан руками до apply — что будет?
?
Ошибка already exists: Terraform его не знает. Нужен terraform import.

Что значит -/+ в плане?
?
Пересоздание: атрибут нельзя поменять на месте — ресурс удалят и создадут заново.

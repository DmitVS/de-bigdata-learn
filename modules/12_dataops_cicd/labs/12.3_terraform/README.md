## Objective

Описать кодом ресурсы внутри стека, которые сейчас создаются руками или скриптами: бакеты,
базы, роли и права. Научиться читать план, хранить состояние удалённо и понимать, как тот же код
выглядел бы для облака.

## Tasks

### Task 1. Ресурсы capstone

**Expected result / Definition of Done:**
- Папка `capstone/infra/terraform/`: бакеты capstone в Silo, роли и права Postgres из лабы 11.3
  (или их часть), state — в бакете `tfstate` с отдельным ключом
- `make tf TF_DIR=capstone/infra/terraform ARGS="plan"` после `apply` показывает `No changes`
- Пароли не лежат в файлах — только переменные `sensitive` из окружения

### Task 2. Импорт и дрейф

**Expected result / Definition of Done:**
- Ресурс, созданный раньше руками (роль или бакет), взят под управление `terraform import`;
  команды и вывод — в README
- Дрейф воспроизведён: ресурс изменён руками, `plan` его показывает, `apply` возвращает к коду
- В README — запись: что случится, если удалить ресурс из кода, и как не удалить данные случайно
  (подсказка: `prevent_destroy`)

### Task 3. Облачный вариант (обзор)

**Expected result / Definition of Done:**
- Файл `capstone/infra/terraform/cloud.md`: таблица «наш сервис → облачный сервис → ресурс
  Terraform» для всего capstone, оценка стоимости в месяц по калькулятору выбранного облака
- Описано, что в облаке добавляется: сети, IAM, окружения dev/prod, где хранить state

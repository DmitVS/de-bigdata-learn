**Модуль:** [04 · Ingestion](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Собрать загрузки лаб 04.1, 04.3 и 04.4 в один повторяемый запуск: `make ingest` приносит в bronze
файлы продаж, справочники учётной системы и промо с праздниками, печатает сводку и не создаёт
дублей при повторе. Это слой capstone, который в модуле 06 возьмёт под управление оркестратор.

## Tasks

### Task 1. Одна точка входа

**Expected result / Definition of Done:**
- `capstone/ingestion/run_all.py` запускает три загрузки по очереди: файлы, учётная система,
  API (промо за даты, которые есть в bronze-продажах, и праздники)
- Цель `ingest` в `Makefile` запускает его в workspace; есть строка справки (`make help`
  показывает `ingest`)
- Падение любой загрузки → ненулевой код выхода `make ingest` и понятное сообщение, какая
  загрузка упала; остальные загрузки при этом выполнены или нет — реши и опиши в README

**Steps:**
1. Загрузки уже существуют — нужно вызвать их функции, а не копировать код.
2. Как `make` передаёт команду в контейнер — посмотри на цели `check` и `data` в `Makefile`.

### Task 2. Сводка запуска

**Expected result / Definition of Done:**
- В конце `make ingest` печатает таблицу: источник → таблица bronze → строк загружено в этом
  запуске → строк в таблице всего → время
- Строки «загружено в этом запуске» берутся из информации dlt о запуске, а не пересчётом всей
  таблицы

### Task 3. Повтор и новые данные

**Expected result / Definition of Done:**
- Два запуска `make ingest` подряд: во втором загружено 0 новых строк продаж, число строк во всех
  таблицах bronze не изменилось (запрос-сверка в `queries.sql`)
- Сценарий «новый день»: доставлен следующий файл продаж, генератор сделал 10 изменений в
  `retail_oltp` → `make ingest` → в bronze появился ровно один новый день продаж, справочники
  сходятся с `retail_oltp` (сверка лабы 04.3), промо за новый день загружены

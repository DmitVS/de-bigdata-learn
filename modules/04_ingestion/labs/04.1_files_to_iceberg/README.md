# Лаба 04.1 · Файлы из S3 `landing` → Iceberg bronze, инкрементально и без дублей

**Модуль:** [04 · Ingestion](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Учётная система сети каждый день кладёт файл продаж в `s3://landing/freshretail/sales/`.
Построить загрузку этих файлов в bronze на dlt: забирать только новые файлы, переживать
повторную доставку без дублей, грузить историю (backfill) и не ломаться при изменении схемы
источника.

### Task 2. Инкрементальная загрузка

**Expected result / Definition of Done:**
- Скрипт `capstone/ingestion/load_sales_files.py` грузит файлы из `landing` в Iceberg-таблицу
  namespace `bronze` через dlt; таблица видна в DuckDB через `ATTACH … TYPE iceberg`
- Каждая строка знает свой файл-источник
- Первый запуск: 350 000 строк. Второй запуск без новых файлов: 0 новых строк, число строк в
  таблице не изменилось — оба запроса в `queries.sql`
- Типы колонок в bronze совпадают с типами в файлах (сравни `DESCRIBE` файла и таблицы)
- Код проходит `make lint`

**Steps:**
1. Источник файлов — `dlt.sources.filesystem` с курсором по времени изменения файла (урок 02,
   шаги 2 и 5).
2. Чтение файла — свой трансформер, отдающий Arrow (урок 02, шаг 4). Подумай, почему не
   встроенный `read_parquet`.
3. Хранилище — `filesystem` с `table_format="iceberg"` и `bucket_url` внутри
   `s3://warehouse/lakehouse/` (урок 02, шаг 7).
4. Имя пайплайна выбери один раз и не меняй (урок 02, ловушка шага 2).

### Task 3. Повторная доставка

**Expected result / Definition of Done:**
- Сначала **предсказание** в README: что будет с числом строк, если повторно доставить
  2024-04-01 и запустить загрузку
- Проверка: повторная доставка → загрузка → запрос. Результат и объяснение в README
- Выбрана и реализована защита от дублей (урок 01, шаг 6): после повторной доставки любого дня
  число строк на ключ `(store_id, product_id, dt)` в таблице или в представлении поверх неё —
  ровно 1. Запрос-проверка `count(*)` против `count(DISTINCT …)` в `queries.sql`
- В README — почему выбран этот способ и чем он плох (время, снапшоты, сложность)

**Steps:**
1. Варианты и их цена — урок 01, шаги 5–6 (замеры merge в Iceberg).
2. Если выбираешь merge, оцени время на весь период до запуска: сколько строк и сколько это
   займёт при измеренной скорости.

### Task 4. Изменение схемы источника

**Expected result / Definition of Done:**

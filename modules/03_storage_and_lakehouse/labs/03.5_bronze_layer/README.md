## Tasks

### Task 1. Контракт bronze-таблицы

**Expected result / Definition of Done:**
- В README: имя таблицы, все колонки с типами (исходные 19 + служебные), партиционирование и
  порядок строк с обоснованием, что считается «как есть» и что ты сознательно добавил
- Служебные колонки минимум: файл-источник и момент загрузки

**Steps:**
1. Bronze не меняет значения и типы источника (модуль 01, урок 04, шаг 4). Подумай, можно ли
   партиционировать по `dt`, если это строка, и что из этого следует.

### Task 2. Скрипт загрузки

**Expected result / Definition of Done:**
- Скрипт `capstone/ingestion/load_bronze_freshretail.py`: создаёт namespace и таблицу, если их нет,
  и загружает оба файла
- Повторный запуск не создаёт дублей — проверено запросом (`count(*)` до и после второго запуска)
- Запуск: `docker compose … exec workspace python capstone/ingestion/load_bronze_freshretail.py`
  (или через `make shell`); код проходит `make lint`

**Steps:**
1. Реши, как сделать повтор безопасным: заменять данные файла-источника (`overwrite_filter`) или
   пропускать уже загруженные файлы (проверка по служебной колонке).
2. Читай Parquet через DuckDB или PyArrow в Arrow-таблицу, добавляй служебные колонки, пиши
   через PyIceberg.

### Task 3. Чтение и сверка

**Expected result / Definition of Done:**
- Из DuckDB (`ATTACH … TYPE iceberg`): число строк, магазинов, товаров и сумма продаж совпадают
  с исходными файлами — запрос-сверка в `queries.sql`
- В [`capstone/README.md`](../../../../capstone/README.md) — раздел о bronze-слое: таблица, как
  загрузить, как проверить
- Пункт DoD модуля «Мини-проект» в ROADMAP отмечен

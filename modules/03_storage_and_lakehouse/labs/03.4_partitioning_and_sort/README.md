## Tasks

### Task 1. Расчёт до эксперимента

**Expected result / Definition of Done:**
- По размеру `sales_hourly.parquet` и числу дней, месяцев, магазинов посчитан ожидаемый размер
  партиции для `day`, `month`, `bucket(16, store_id)` — в README с выводом, какие варианты
  создадут мелкие файлы
- Выбраны 3 типовых запроса из карточек модуля 01: (а) один день по сети; (б) один магазин за
  весь период; (в) один магазин за неделю

### Task 2. Четыре раскладки

**Expected result / Definition of Done:**
- Четыре Iceberg-таблицы одних и тех же 116,4 млн строк: A — без партиций, без сортировки;
  B — `day(sale_date)`; C — `month(sale_date)` + сортировка по `store_id, product_id`;
  D — без партиций + сортировка по `store_id, product_id, sale_date`
- Для каждой: число файлов, средний размер файла, число партиций (`inspect.partitions()`)

**Steps:**
1. Читай silver-файл в Arrow (`to_arrow_table()`), при необходимости с `ORDER BY` (урок 05, шаг 4).
2. Партиции — через `PartitionSpec` (урок 05, шаг 2). Не забудь, что `pyiceberg-core` нужен для
   преобразований.
3. Целевой размер файлов оставь по умолчанию — посмотри, сколько файлов получится сам.

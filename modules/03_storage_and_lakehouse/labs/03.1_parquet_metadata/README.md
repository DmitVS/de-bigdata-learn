## Objective

Научиться проверять Parquet-файл до того, как строить на нём пайплайн: схема, группы строк,
кодирование, статистики. На файлах FreshRetail найти, что в них сделано хорошо и что плохо для
наших запросов, и доказать это числами из подвала.

## Tasks

### Task 1. Паспорт файла

**Expected result / Definition of Done:**
- Скрипт печатает для `train.parquet` и `eval.parquet`: строки, группы строк, строк в группе
  (минимум, максимум), число колонок, размер подвала и его доля от файла, `created_by`
- В README: таблица «колонка → физический тип → кодек → кодировки → сжатый размер →
  коэффициент сжатия» для всех колонок `train.parquet`, отсортированная по сжатому размеру

**Steps:**
1. Открой файл через `pq.ParquetFile`, обойди `row_group(i).column(j)` и просуммируй размеры по
   колонкам (урок 01, шаг 4).
2. Коэффициент сжатия — `uncompressed / compressed`.
3. Размер файла — `os.path.getsize`.

### Task 2. Порядок строк и отсечение

**Expected result / Definition of Done:**
- Ответ с доказательством из статистик: по каким колонкам упорядочены строки файла
- Таблица: для 4 фильтров — `store_id = 214`, `product_id = 38`, `dt = '2024-05-01'`,
  `city_id = 3` — сколько групп строк из 4 500 могут содержать нужные строки
- Объяснение каждой цифры через порядок строк

**Steps:**
1. Посмотри min/max нескольких колонок в первых и последних группах.
2. Посчитай группы, где значение попадает в `[min, max]`, двумя способами: в Python и через
   `parquet_metadata` в DuckDB (урок 01, шаг 4). Результаты должны совпасть.

### Task 3. Перезапись и её эффект

**Expected result / Definition of Done:**
- `train.parquet` перезаписан в `data/rewrite/` в двух вариантах: группы по умолчанию и группы с
  сортировкой по `dt, store_id`
- Таблица: размер файла, групп, подвал, групп под фильтр `dt = '2024-05-01'` и под
  `store_id = 214` — для исходного файла и обоих вариантов
- Вывод: какой порядок строк лучше для запросов «за день» и «по магазину» и почему нельзя
  выиграть оба сразу одной сортировкой

**Steps:**
1. Перезапиши через `COPY … TO … (FORMAT parquet)` в DuckDB; второй вариант — с `ORDER BY`.
2. Повтори подсчёт групп из Task 2 для новых файлов.
3. `mkdir -p data/rewrite` в `make shell`; папка не попадёт в git.

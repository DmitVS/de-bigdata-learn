# Лаба 10.4 · Семантический слой: метрики capstone в одном месте

**Модуль:** [10 · Витрины и BI](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Описать ключевые метрики сети один раз в dbt-проекте capstone и добиться, чтобы Superset,
Evidence и аналитик (`mf query`) получали одно число на один вопрос. Тренируем семантические
модели, ratio-метрики и сверку определений.

## Tasks

### Task 1. Семантические модели

**Expected result / Definition of Done:**
- Календарь (time spine) и семантические модели для факта продаж, магазинов и товаров в
  capstone; `mf validate-configs --skip-dw` — без ошибок
- `mf list dimensions --metrics <метрика>` показывает разрезы по городу, категории, промо, дате

**Steps:**
1. Опиши сущности так, чтобы MetricFlow сам находил путь к справочникам.
2. Проверь каждую связь запросом с `--group-by` через справочник.

### Task 2. Метрики сети

**Expected result / Definition of Done:**
- Не меньше пяти метрик с `label` и `description`: продажи, часы без товара, доля часов без
  товара, доля продаж в промо, ещё одна по выбору (например, продажи на магазин в день — `derived`)
- Каждая сверена с ручным SQL на двух разрезах; запросы и числа — в README
- Найден и описан хотя бы один случай, где наивная формула даёт другое число (среднее долей и т.п.)

**Steps:**
1. Сначала запиши определение метрики словами: числитель, знаменатель, какие строки входят.
2. Опиши метрику в YAML и проверь `--explain`.
3. Сверь с ручным SQL.

### Task 3. Одно число везде

**Expected result / Definition of Done:**
- Для двух метрик: `mf query`, чарт Superset (лаба 10.3) и отчёт Evidence (лаба 10.5) дают одно
  число на одном разрезе; таблица сверки — в README
- В README — правило команды: где живёт определение, кто меняет формулу и как изменение
  доходит до Superset

**Steps:**
1. Выбери разрез (например, город 0 за май) и получи число тремя способами.
2. Если числа расходятся — найди причину по SQL каждого инструмента и исправь.

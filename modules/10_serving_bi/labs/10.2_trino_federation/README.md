**Модуль:** [10 · Витрины и BI](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Ответить на вопрос, для которого нет готовой витрины: соединить продажи из lakehouse с текущим
справочником учётной системы и с итогами в ClickHouse одним SQL. Понять, что Trino отдаёт
источникам (pushdown), а что делает сам, и во что это обходится.

## Tasks

### Task 1. Три каталога

**Expected result / Definition of Done:**
- `SHOW CATALOGS` показывает `iceberg`, `postgresql`, `clickhouse`; в каждом найдены свои таблицы
- В README — где описан каждый каталог и откуда Trino берёт пароли и ключи S3

**Steps:**
1. Открой `make trino` и пройди `SHOW SCHEMAS FROM …`, `SHOW TABLES FROM …` для каждого каталога.
2. Найди файлы каталогов в `infra/docker/trino/catalog/` и прочитай их.

### Task 2. Федеративный вопрос

**Expected result / Definition of Done:**
- Вопрос сформулирован в README бизнес-языком, например: «продажи и часы без товара за последние
  30 дней датасета по магазинам, которые **сейчас** закрыты в учётной системе»
- Один SQL в Trino соединяет витрину Iceberg и `retail_oltp`; результат сверен с отдельными
  запросами к каждому источнику
- Перед запуском генератора изменений `retail_oltp` (модуль 04) и после — ответ меняется без
  перестройки витрин; вывод «до» и «после» — в README

**Steps:**
1. Запиши запрос в файл `capstone/serving/trino/<вопрос>.sql`.
2. Запусти его `make trino ARGS="--file /…"` (подумай, по какому пути Trino видит файл, или передай
   запрос через `--execute`).
3. Запусти `scripts/retail_oltp_changes.py` и повтори запрос.

### Task 3. Что Trino отдаёт источникам

**Expected result / Definition of Done:**
- `EXPLAIN` федеративного запроса: в README отмечено, какие фильтры и агрегаты ушли в Postgres и
  ClickHouse (pushdown), а какие Trino выполняет сам
- `EXPLAIN ANALYZE`: сколько строк Trino получил от каждого источника
- Запрос переписан так, чтобы из источников приходило меньше строк; замер «до» и «после»

**Steps:**
1. Найди в плане узлы `TableScan` и их параметры; сравни с текстом запроса.
2. Найди в журнале Postgres (`pg_stat_statements` нет — используй `log_statement` через
   `ALTER SYSTEM`, или `pg_stat_activity` во время запроса) SQL, который пришёл от Trino.
3. Измени запрос (фильтр раньше, агрегат в подзапросе) и повтори замер.

  ClickHouse; критерии решения

**Steps:**

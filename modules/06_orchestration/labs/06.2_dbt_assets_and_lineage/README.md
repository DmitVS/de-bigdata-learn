## Tasks

### Task 1. dbt-проект на графе

**Expected result / Definition of Done:**
- `capstone/transform` подключён через `@dbt_assets`; сборка идёт с целью, которая публикует
  витрины в Iceberg (модуль 05, урок 02)
- Каждый `source()` dbt сопоставлен с ассетом загрузки из 06.1: на графе нет «висящих» ассетов
  источников, `asset list --select "*<твоя витрина>"` включает ассеты bronze
- Тесты dbt видны проверками на моделях; число проверок совпадает с числом тестов в
  `dbt ls --resource-type test` (обе цифры в README)

**Steps:**
1. Где dbt-ассеты будут писать файл DuckDB и кто ещё его открывает? Нужен ли пул (урок 03, шаг 6)?
2. Как dagster-dbt называет ассет источника по умолчанию? Сравни с ключами из 06.1.

### Task 2. Своя блокирующая проверка

**Expected result / Definition of Done:**
- `@asset_check` на ассете продаж bronze: правило полноты дня, выбранное по данным (сколько
  строк или пар магазин × товар должно быть в дне — проверь запросом)
- Проверка блокирующая; в README — почему именно эта проверка на этом ассете

### Task 3. Разбор сбоя по графу

**Expected result / Definition of Done:**
- Сбой воспроизведён: например, повторная доставка файла дня со сдвигом схемы
  (`landing_drop.py --drift rename`) или удаление части строк дня в bronze. Что сделал — в README
- Проверка или тест его поймали; в README — что увидел в UI и в каком ассете
- Таблица в README: какие ассеты затронуты (по графу), какие партиции, какой выбор `--select`
  ты запускаешь и почему не меньше и не больше
- После перерасчёта все проверки зелёные, витрина совпадает с состоянием до сбоя (запрос-сверка)

**Steps:**
1. Прежде чем чинить, запиши предсказание: какие ассеты станут неактуальными.
2. Сравни два способа восстановления: Re-execute from failure и выбор `x*`. Когда какой?

# Лаба 06.5 · Мини-проект: pipeline 03–05 под оркестратором

**Модуль:** [06 · Оркестрация](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Весь pipeline capstone — от файла в landing до витрин в Iceberg `gold` — запускается сам: загрузка
по появлению данных и расписанию, витрины по обновлению входов. Падения видны в UI, плохие данные
останавливаются проверками, а инструкция дежурного объясняет, что делать при сбое.

## Tasks

### Task 1. Автоматический pipeline

**Expected result / Definition of Done:**
- Загрузка продаж — сенсор и/или расписание; справочники и промо — по расписанию; dbt-модели —
  по обновлению входов (`AutomationCondition`), без расписания «с запасом»
- Сценарий «новый день» без ручных запусков: `landing_drop.py` следующего дня + 10 изменений в
  `retail_oltp` → через несколько минут витрины `gold` содержат новый день (запрос)

### Task 2. Сбои видны и останавливают плохие данные

**Expected result / Definition of Done:**
- Ретраи на загрузках из внешних систем (API, S3); у шагов, которые нельзя повторять, — нет
- Блокирующие проверки на bronze; dbt-тесты — проверки
- Два проверенных сценария: (1) `RETAIL_API_FAIL_RATE=0.5` — ретраи справляются или запуск
  падает, и это видно; (2) испорченный день — витрины не обновляются, проверка красная

### Task 3. Инструкция дежурного

**Expected result / Definition of Done:**
- В [`capstone/README.md`](../../../../capstone/README.md) — раздел «Orchestration»: граф (Mermaid),
  что запускается чем, как поднять, где смотреть, и runbook «симптом → что проверить → что
  пересчитать (выбор `--select`)» минимум на 4 сбоя
- Пункты DoD модуля 06 в [`ROADMAP.md`](../../../../ROADMAP.md) отмечены по факту

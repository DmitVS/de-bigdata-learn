# Лаба 07.5 · Мини-проект: восстановленный спрос при out-of-stock на Spark

**Модуль:** [07 · Батч-обработка: Spark](../../README.md) · **Дата начала:** YYYY-MM-DD · **Статус:** ⬜

## Objective

Построить на Spark тяжёлую витрину «восстановленный спрос»: сколько товара сеть продала бы в
часы, когда его не было на полке. Это ответ на бизнес-вопрос о потерях от out-of-stock (модуль
01, скрытый спрос) и вклад в capstone.

## Tasks

### Task 1. Метод

**Expected result / Definition of Done:**
- В README — метод восстановления, выбранный тобой и обоснованный (например, средние продажи того
  же товара в том же магазине в тот же час в дни, когда товар был в наличии), его допущения и
  ограничения; grain витрины
- Метод сверен на одном магазине и товаре вручную (запрос + расчёт)

### Task 2. Реализация

**Expected result / Definition of Done:**
- Трансформации — чистые функции с тестами (как в 07.2)
- Витрина пишется в Iceberg `gold` атомарно, партиционирована осмысленно; число файлов на
  партицию разумно (проверка по `t.files`)
- Перекос и тяжёлые shuffle проверены в UI; если были — что сделано

### Task 3. Ответ бизнесу и capstone

**Expected result / Definition of Done:**
- Запрос к витрине: доля потерянных продаж по сети, топ-10 магазинов и категорий по потерям
- Витрина читается из DuckDB, суммы совпадают
- В [`capstone/README.md`](../../../../capstone/README.md) — раздел «Spark»: витрина, метод,
  как собрать, как проверить; пункты DoD модуля 07 в [`ROADMAP.md`](../../../../ROADMAP.md)
  отмечены по факту
- (по желанию) сборка витрины — ассет Dagster (модуль 06)

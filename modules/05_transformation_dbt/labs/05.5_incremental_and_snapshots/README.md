## Tasks

### Task 1. Инкрементальный факт

**Expected result / Definition of Done:**
- `fct_sales_daily` (или новая модель) — incremental со стратегией и ключом, выбранными в
  README, и окном перечитывания
- Проверка: полная сборка (`--full-refresh`) и сборка «полная за период минус 3 дня + инкремент»
  дают одинаковые число строк и суммы (запрос в README)
- Поздние данные: изменение строки за день внутри окна попадает в факт, за день вне окна — нет;
  оба случая проверены и объяснены

### Task 2. Snapshots справочников

**Expected result / Definition of Done:**
- Snapshots магазинов, товаров и ассортимента из bronze; стратегия для каждого выбрана с учётом
  того, что ты узнал о `updated_at` в модуле 04; удаления отмечаются
- Сценарий: snapshot → генератор `--changes 20` → загрузка `make ingest` → snapshot. В истории
  видны смена статуса, смена категории и удаление из ассортимента (запросы в README)

### Task 3. Измерение SCD2

**Expected result / Definition of Done:**
- `dim_product` (или отдельная модель) строится поверх snapshot: версии, суррогатный ключ версии,
  `is_current`
- Point-in-time join: продажи товара, сменившего категорию, относятся к категории, действовавшей
  в день продажи; число строк факта после соединения не изменилось

### Task 4. Публикация в Iceberg

**Expected result / Definition of Done:**
- Витрины marts публикуются в namespace `gold` при сборке с целью, подключающей каталог
- Из чистого DuckDB (`ATTACH … TYPE iceberg`) витрины `gold` читаются, суммы совпадают с DuckDB-
  файлом
- В README — что видит читатель во время публикации и почему (урок 02, шаг 5)

## Tasks

### Task 1. Описания

**Expected result / Definition of Done:**
- У всех моделей marts и всех их колонок есть описания; у моделей — grain и бизнес-вопрос
- Минимум два docs-блока, использованных в нескольких местах
- `persist_docs` включён; комментарии видны в DuckDB запросом (в README)

### Task 2. Сайт и граф

**Expected result / Definition of Done:**
- `dbt docs generate` + `dbt docs serve` на порту 8580 открываются с хоста
- Exposure для будущего дашборда (модуль 10) с зависимостями от витрин
- Скриншот графа от источников до exposure — в README

### Task 3. Анализ влияния

**Expected result / Definition of Done:**
- Ответы командами (вывод в README): что затронет изменение staging-модели продаж; от чего
  зависит `fct_sales_daily`; какие модели нужны exposure
- Сценарий: источник переименовал колонку — перечислено, что править и что пересобрать

### Task 4. Проверка описаний

**Expected result / Definition of Done:**
- Скрипт `capstone/transform/scripts/check_docs.py` читает `target/manifest.json` и завершается с
  ненулевым кодом, если у модели marts нет описания модели или любой её колонки; печатает
  нарушителей
- Проверено: убрал описание — скрипт упал с кодом 1 и назвал модель; вернул — код 0
- Скрипт проходит `make lint`

**Steps:**
1. Структура manifest — урок 04, шаг 6. Модели marts можно отличить по пути или `fqn`.
2. Коды выхода — модуль 00, урок 05.

## Tasks

### Task 1. Generic-тесты

**Expected result / Definition of Done:**
- Ключ каждой модели staging и marts проверен (`unique` + `not_null` или составной ключ)
- Факт проверен `relationships` на все измерения; статус магазина — `accepted_values`; доли — в
  диапазоне [0, 1]
- Строгость выбрана осознанно: где «сироты» из bronze допустимы — предупреждение, в marts —
  ошибка (обоснование в README)

### Task 2. Сингулярный и свой generic-тест

**Expected result / Definition of Done:**
- Сингулярный тест сверки: сумма продаж в факте за каждый день равна сумме в staging
- Свой generic-тест, применённый минимум к двум колонкам разных моделей

### Task 3. Unit-тесты

**Expected result / Definition of Done:**
- Минимум два unit-теста на формулы витрин (доля часов без остатка, признак промо или другое
  нетривиальное), фикстуры содержат граничные случаи (ровно на пороге, NULL, пустая группа)
- Проверено, что тест ловит ошибку: внесена ошибка в формулу → тест упал → ошибка откачена.
  Вывод дифа — в README

**Steps:**
1. Ловушка с ephemeral-входами — урок 03, шаг 5.

### Task 4. Плохие данные

**Expected result / Definition of Done:**
- Сценарий: в bronze появился дубль (повторная доставка без защиты или ручная вставка в
  песочнице) → `dbt build` → какие тесты упали, какие модели пропущены
- Нарушения сохранены (`store_failures`) и разобраны запросом; в README — путь от упавшего
  теста к причине
- После устранения причины сборка зелёная

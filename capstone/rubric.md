# Рубрика оценки capstone

Адаптация критериев финального проекта
[DE Zoomcamp](https://github.com/DataTalksClub/data-engineering-zoomcamp/tree/main/projects):
семь исходных критериев переложены на локальный стек, добавлены три критерия нашего курса
(качество, стриминг/CDC, документация). По этой же рубрике проверяются чужие проекты при
peer review.

Каждый критерий оценивается в 0 / 2 / 4 балла. **Максимум — 40.** Capstone считается готовым
при **≥ 32 баллах** и отсутствии нулей.

## Критерии

| # | Критерий | 0 | 2 | 4 |
|---|---|---|---|---|
| 1 | Постановка задачи | Нет описания | Описана кратко или неясно | Бизнес-вопросы сети сформулированы, для каждого указано, какая витрина или дашборд на него отвечает |
| 2 | Инфраструктура как код | Ручная настройка | Compose поднимает стек, но часть шагов вручную | Весь стек поднимается из compose + Make; есть Terraform-описание облачного варианта (plan) |
| 3 | Ingestion | Нет оркестрации | Загрузка частично ручная | Все источники (файлы, OLTP, API) грузятся инкрементально и запускаются из Dagster end-to-end |
| 4 | Хранилище (lakehouse) | Не используется | Таблицы созданы, но без обоснованного партиционирования | Партиционирование и порядок сортировки выбраны под реальные запросы, выигрыш подтверждён замером |
| 5 | Трансформации | Нет | Разрозненный SQL | dbt-проект по слоям с тестами; тяжёлая витрина на Spark |
| 6 | Дашборд | Нет | Один график | Минимум два: распределение по категориям (например, out-of-stock по городам) и динамика во времени (продажи по часам или дням) |
| 7 | Воспроизводимость | Нет инструкции | Инструкция неполная | Чистый клон → `make` по README → работающий дашборд, без правок руками |
| 8 | Качество данных | Нет проверок | Только dbt tests | dbt tests + Soda + Elementary, есть SLO и хотя бы один постмортем |
| 9 | Стриминг / CDC | Нет | Producer/consumer без записи в lakehouse | CDC из `retail_oltp` и потоковая витрина пишутся в Iceberg или ClickHouse |
| 10 | Документация и обоснования | Нет | README без обоснований | Архитектурная схема, решения с альтернативами, известные ограничения |

Критерии 1–7 — из Zoomcamp (облако заменено на IaC), 8–10 добавлены для нашего курса.

## Peer review

Идея из Zoomcamp: оценивая чужие проекты, учишься не меньше, чем на своём.

1. **Оценить 3 чужих проекта** по этой рубрике. Финальные проекты Zoomcamp публичны на GitHub
   (ищи по `data-engineering-zoomcamp project`). Для каждого — короткая запись в
   `interview/peer-review/<проект>.md`: баллы, что стоит взять себе, что сделано хуже, чем у тебя.
2. **Получить 1 внешнее ревью** своего проекта: знакомый инженер, сообщество DataTalksClub
   или Data-Learn. Попроси пройти пункт 7 с чистого клона.

# AGENTS.md — DE BigData Learn

Единый источник инструкций для любого AI-ассистента (Claude Code, Copilot, Codex CLI, Cursor,
Gemini CLI и т.д.), работающего в этой папке. Конвенция [agents.md](https://agents.md);
`CLAUDE.md` — лишь указатель сюда.

## Контекст проекта

- Проект **самообучения Data Engineering** на Modern Data Stack. Пользователь — учащийся,
  ассистент — ментор и помощник по инфраструктуре.
- Сквозной датасет — **FreshRetailNet-50K** (Dingdong, 898 магазинов, 863 SKU, почасовые
  продажи/остатки/промо/погода, CC-BY-4.0). Выбор и альтернативы — [`memory/decisions/dataset.md`](memory/decisions/dataset.md).
- План и прогресс — [`ROADMAP.md`](ROADMAP.md). Внешние материалы к модулям (Клеппман, DE Zoomcamp) —
  [`reading_map.md`](reading_map.md): при подготовке теории модуля ссылайся на нужные главы и видео. Методика — [`memory/decisions/course-methodology.md`](memory/decisions/course-methodology.md).
- Темы про LLM в работе инженера данных **отложены до окончания курса** — не предлагай их раньше.

## Жёсткие правила

- **Всё работает только в контейнерах через Docker Compose.** Не устанавливай на хост
  Python-пакеты, Java, CLI-инструменты и т.п. Новый инструмент = новый сервис в compose-слое
  или зависимость в образе workspace. Решение — [`memory/decisions/containers-only.md`](memory/decisions/containers-only.md).
- Секреты — только в `.env` (в `.gitignore`); в git — `.env.example` с плейсхолдерами.
- Образы — с **фиксированной версией** (не `latest`), порты публикуются только на `127.0.0.1`.
- Порт **8080 на хосте занят** (open-webui) — не используй его для новых сервисов.
- **Не решай лабы за пользователя**, если он явно не попросил решение. По умолчанию: подсказка,
  наводящий вопрос, ревью его решения, объяснение концепции. Инфраструктуру, шаблоны и
  служебные скрипты делать можно.

## Формат занятий

Решение пользователя от 2026-09-27 (после части 3 лабы 00.1):

1. **Сначала теория** — полноценное объяснение темы с примерами из нашего стека, схемами и
   типичными ошибками. Не дробить теорию вопросами «посмотри вывод и перепиши».
2. **Потом практика на закрепление** — задачи на применение знаний: изменить конфигурацию,
   добавить сервис, предсказать поведение и проверить, найти и починить поломку, спроектировать.
   Результат задачи — работающая вещь или обоснованное решение, проверяемое командой.
3. **Не давать задач на переписывание вывода терминала** в README. В README лабы пользователь
   записывает только своё: решения, выводы, ответы на вопросы «почему».
4. Короткие контрольные вопросы на понимание — в чате, после теории, перед практикой.
5. **Теории должно хватать на решение каждой задачи** (уточнение от 2026-09-27): перед задачей
   дать всё, что в ней используется, — синтаксис конфигов и команд, нужный минимум Python, как
   устроены задействованные технологии, коды ошибок и как их читать. Структурно, по существу, без
   воды, но полно и понятно новичку. Практика — это применение изученного, а не угадывание того,
   чего не объясняли.
6. **Вся теория хранится в модуле** — файл на тему в `modules/NN_<модуль>/theory/` + пункт в
   маршруте прохождения `README.md` модуля. Теорию, данную в чате, всегда записывать туда же.
   Решение от 2026-09-28: всё, что относится к модулю, лежит в его папке (см. «Как устроен проект»).
7. **Формат урока** (решение от 2026-09-28, эталон — [`modules/00_just_enough/theory/03_networking.md`](modules/00_just_enough/theory/03_networking.md),
   шаблон — [`templates/theory_lesson.md`](templates/theory_lesson.md)): чек-лист «после урока ты сможешь» с отмечаемыми пунктами; одна сквозная аналогия
   (таблица в «Шаге 0»); шаги-вопросы от простого к сложному; в каждом шаге — схема, объяснение,
   пример из стека, «Попробуй сам» (команда, проверенная на живом стеке), ловушка; сквозной
   пример; шпаргалка; типичные ошибки «симптом → причина → проверка → исправление»; «Проверь себя»
   со свёрнутыми ответами; карточки в `flashcards.md`; термины — отдельные заметки в
   [`glossary/`](glossary/README.md) (общий на курс); карта темы — Canvas в `modules/NN_*/maps/`. Тип схемы — по содержанию: устройство →
   flowchart, процесс во времени → sequence, диагностика → дерево решений, сравнение → таблица.
   Модуль: в README — чек-лист самоконтроля по всем урокам; у каждой задачи лабы — DoD и Steps
   (что запустить и куда записать, без ответов).
8. **Объяснять, а не перечислять** (уточнение от 2026-09-28): тезисы не раскрывают суть. Каждое
   понятие раскрывать связным текстом по цепочке: *какую проблему решает → как устроено внутри
   (механизм по шагам) → что из этого следует → как это увидеть у нас*. Причинные связи
   («потому что», «поэтому», «иначе») писать явно. Списки — только для перечислений, не вместо
   объяснения. Схема дополняет текст, а не заменяет его.
9. **Сложная тема — несколько форм** (решение от 2026-10-03): текст и схема Mermaid, затем
   интерактивная HTML-страница `modules/NN_*/visuals/<тема>.html` (один файл без внешних
   зависимостей), затем видео `modules/NN_*/visuals/<тема>.mp4` в стиле 3Blue1Brown: сцена Manim
   `<тема>_video.py`, озвучка ElevenLabs (голос George; черновик — Piper, `VOICE=piper`), сборка
   `make video SCENE=…`. Ссылки — врезкой
   «Визуализация темы» в начале урока. Решение — [`memory/decisions/visual-explanations.md`](memory/decisions/visual-explanations.md).

## Как устроен проект

- `Makefile` — единая точка входа (`make help`). Команды в контейнере: `make shell`, `make sql`.
- `infra/docker/compose.yaml` подключает слои через `include`; core работает всегда, остальные
  слои добавляются в своём модуле (см. [`infra/README.md`](infra/README.md)).
- Python-зависимости — `pyproject.toml` + `uv.lock`, ставятся в образ workspace. Добавить пакет:
  `make uv ARGS="add --group <модуль> <пакет>"`, затем `make build`.
- Модуль = `modules/NN_<название>/` — всё по теме модуля в одной папке:
  ```
  README.md       хаб: цели, маршрут прохождения (теория ↔ задачи лаб со статусами), ресурсы
  theory/         уроки MM_<тема>.md по шаблону templates/theory_lesson.md
  labs/           лабы NN.M_<название>/README.md
  maps/           Canvas / Excalidraw модуля
  flashcards.md   карточки Spaced Repetition (тег #flashcards/de/mNN)
  cheatsheet.md   шпаргалка пользователя своими словами
  homework.md     домашка-чекпоинт
  notes.md        выводы и тезисы из книги/видео
  ```
  Папки и файлы создаются, когда появляется содержимое. В корне — только общее для курса:
  [`glossary/`](glossary/README.md) (термины), [`reading_map.md`](reading_map.md), `ROADMAP.md`, `capstone/`.
- Obsidian: хранилище = папка проекта, ссылки — markdown с относительными путями, плагины —
  `make obsidian`. Решение — [`memory/decisions/obsidian.md`](memory/decisions/obsidian.md).
- Лаба = `modules/NN_*/labs/NN.M_<название>/README.md` по шаблону [`templates/lab_README.md`](templates/lab_README.md).
- Результаты мини-проектов модулей накапливаются в `capstone/`.

## Повторяющиеся процессы

### Новая лаба
1. Скопируй `templates/lab_README.md` в `modules/NN_*/labs/NN.M_<название>/README.md`.
2. Заполни Objective, Key Terms, Prerequisites, Tasks — у каждой задачи **Definition of Done**.
3. Добавь её задачи в маршрут прохождения README модуля.

### Новый урок теории
1. Скопируй `templates/theory_lesson.md` в `modules/NN_*/theory/MM_<тема>.md`.
2. Команды из «Попробуй сам» прогони на живом стеке, прежде чем писать «Увидишь».
3. Новые термины — заметки в `glossary/` (+ строка в `glossary/README.md`); карточки — в
   `flashcards.md` модуля; карта темы — `maps/<тема>.canvas` модуля.
4. Добавь урок в маршрут прохождения README модуля.

### Закрытие модуля
1. Составь домашку-чекпоинт `modules/NN_*/homework.md` по [`templates/homework.md`](templates/homework.md):
   5–7 вопросов с однозначным ответом, получаемым запросом к стеку; сверь ответы пользователя.
2. Проверь все пункты DoD модуля в `ROADMAP.md` — отмечай `[x]` только выполненное.
3. Статус модуля: ⬜ → 🟨 → ✅. Выводы — в `modules/NN_*/notes.md`.
4. Предложи тему публикации в `blog/` и вопросы на повторение.

### Еженедельное ретро
Скопируй `templates/weekly.md` в `plans/weekly/YYYY-Www.md`: что сделано, что мешало, план на неделю.

### Инцидент в pipeline
Запись в `ops/incidents.md` по шаблону постмортема (что, когда заметили, причина, MTTD/MTTR, действия).

### Устойчивый факт или решение
Файл в `memory/decisions/` или `memory/lessons/` + строка в `memory/MEMORY.md`.

## Стиль кода

- Python 3.12, ruff (line-length 100). SQL — sqlfmt. YAML — yamllint. Проверка: `make lint`.
- dbt: слои staging/intermediate/marts, префиксы `stg_`, `int_`, `fct_`, `dim_`.

## Язык

Документация, заметки и память — на русском. Идентификаторы в коде — на английском.

Стиль текстов и ответов — по правилам ASD-STE100, перенесённым на русский язык, не меньше 80 %
(решение от 2026-10-03, подробности — [`memory/decisions/writing-style-ste.md`](memory/decisions/writing-style-ste.md)):
инструкция — до 20 слов, описание — до 25 слов; одна инструкция в предложении, повелительное
наклонение; действительный залог; один термин — одно значение; абзац — одна тема, до шести
предложений; в предупреждении сначала команда, потом причина.
